# Análisis y Diseño de Sistemas — Guía de estudio

## 1. Fundamentos
- **Sistema**: conjunto de componentes que interactúan para lograr un objetivo; entrada, proceso, salida, retroalimentación.
- **Sistema de información (SI)**: conjunto de datos, procesos, personas y tecnología.
- Análisis vs Diseño:
  - **Análisis**: qué debe hacer el sistema (relevamiento y requisitos).
  - **Diseño**: cómo hacerlo (arquitectura y detalle técnico).
- Ciclo de vida del software (SDLC): planificación → análisis → diseño → implementación → pruebas → mantenimiento.
- Roles: analista, diseñador, programador, tester, usuario, cliente, gestor de proyecto.

## 2. Modelos de proceso de software
- Cascada (waterfall): fases secuenciales.
- Incremental / iterativo.
- Espiral.
- Ágiles: Scrum (sprints, roles, artefactos), Kanban.
- Ventajas y desventajas de cada uno.

## 3. Relevamiento de requisitos
- Técnicas: entrevistas, encuestas/cuestionarios, observación, análisis de documentos.
- **Requisitos funcionales**: qué funciones debe cumplir el sistema.
- **Requisitos no funcionales**: rendimiento, seguridad, usabilidad, disponibilidad, mantenibilidad.
- **Requisitos de usuario** vs **requisitos de sistema**.
- Validación y documentación de requisitos (especificación de requisitos).

## 4. Modelado con UML (Lenguaje Unificado de Modelado)
- **Casos de uso**: actores, escenarios, relaciones (include, extend, generalize).
- **Diagrama de casos de uso**: visión funcional del sistema.
- **Diagrama de clases**: estructura estática (clases, atributos, métodos, relaciones).
- **Diagrama de secuencia**: interacción temporal entre objetos (mensajes, lifelines).
- **Diagrama de actividades**: flujo de trabajo/proceso.
- Otros: diagrama de estados, de componentes, de despliegue.
- Reglas: identificar actores y casos de uso desde los requisitos.

## 5. Diseño del sistema
- Arquitectura: cliente-servidor, capas (presentación/lógica/datos), MVC, 3-capas.
- Diseño de base de datos (modelo E/R, diccionario de datos).
- Diseño de interfaz de usuario (wireframes, prototipos).
- Patrones de diseño básicos: Singleton, Factory, Observer, MVC (introducción).

## 6. Entregables típicos
- Documento de requerimientos, modelo de casos de uso, modelo de dominio,
- Diagramas UML, prototipo de UI, diseño de BD, plan de pruebas.

## 7. Puntos de examen frecuentes
- Diferencia entre análisis y diseño; entre requisitos funcionales y no funcionales.
- Dado un enunciado: identificar actores y casos de uso, y dibujar el diagrama.
- Explicar el ciclo de vida y elegir modelo según el proyecto.
- Explicar la relación include/extend entre casos de uso.
- Diferencias entre modelo de proceso cascada y Scrum.

## Guía rápida
Si ERIS te pregunta sobre Análisis y Diseño de Sistemas: cubre ciclo de vida,
requisitos (funcionales/no funcionales), UML (casos de uso, clases, secuencia),
arquitectura por capas y Scrum, aplicado a enunciados prácticos.
