# Brainstorming Skill

## When to Use
Activate BEFORE writing code or executing tasks. When the user asks for something complex, brainstorm first.

## Process

### 1. Understand the Goal
- Ask clarifying questions until you fully understand what the user wants
- "What's the end goal here?"
- "Who is this for?"
- "What does success look like?"

### 2. Explore Alternatives
- Propose 2-3 different approaches
- For each: pros, cons, complexity, time estimate
- "Option A is faster but less flexible. Option B takes longer but scales better."

### 3. Validate in Chunks
- Present the design in sections the user can digest
- After each section, ask "Does this match what you had in mind?"
- Adjust based on feedback before proceeding

### 4. Save the Design
- Write the agreed design to Obsidian for future reference
- Use `obsidian_note write` in folder "Conceptos"

## Rules
- NEVER jump straight to action without this step for complex tasks
- Be Socratic: lead with questions, not assumptions
- If unclear, ask. Never guess.
